# 8D 环绕穿梭 — Audacity 8D 声像插件

> 一个用 Nyquist 重写的 Audacity 8D 环绕声像效果插件。
> 从 44 行「能左右响」的脚本，做到 11 个参数可调、六个机制齐全的成品。

[![Audacity](https://img.shields.io/badge/Audacity-3.7%2B-blue)](https://www.audacityteam.org/)
[![Nyquist](https://img.shields.io/badge/Nyquist-v4-green)](https://manual.audacityteam.org/man/nyquist.html)
[![License: GPL v2+](https://img.shields.io/badge/License-GPLv2%2B-orange)](LICENSE)

## 这是什么

网上流传的「穿脑效果」类插件，多数只做了**左右声道的音量交替**。听起来确实在动，
但和短视频平台上的爆款 8D 环绕音乐差距明显 —— 只是"能左右响"，谈不上"好听"。

这个项目做的是：**先逆向分析出差距在哪，再重新设计实现。**

原版插件的全部逻辑只有 44 行，参数全部写死、没有任何可调控件：

```lisp
(setf mono (mult mix-scale (sum left-orig right-orig)))   ; 混成单声道
(vector (mult mono left-env)                              ; 左声道乘包络
        (mult mono right-env))                            ; 右声道乘反相包络
```

本项目把它重写为 **11 个可调参数 + 6 个固定档位**，并补齐了缺失的六个关键机制。

---

## 六个关键机制

我没有靠"改参数试听"找差距，而是逐条推导听感差异背后的物理原因：

| # | 机制 | 解决的根因 |
|---|---|---|
| 1 | **等功率声像** `L=cos(θ), R=sin(θ)` | 原版线性曲线（`0.6±0.4·sin`）使**单耳**在中间比极端低 **4.44 dB**，每周期出现两个响度谷 |
| 2 | **Haas 延迟**（默认 18 ms） | 纯音量差（ILD）只能让声音在颅内移动；**时间差（ITD）** 才是"跑出头外"的来源。原版**一个延迟元件都没有** |
| 3 | **低频保护**（默认 200 Hz 分频） | 100 Hz 波长约 3.4 m，两耳相位差不足以定位 → 低频横扫只产生"呼吸感"、鼓点发虚 |
| 4 | **干湿比**（默认保留 25% 原声） | 100% 湿信号会让人声失焦、声场发空 |
| 5 | **BPM 卡点 + 相位偏移** | 原版周期写死 10 秒且相位绝对不可控，永远对不上拍 |
| 6 | **输出归一化** | 防止削波，并让 A/B 对比响度公平 |

### 一个设计细节：为什么不自己建正弦波表

最初想用 `build-harmonic` 自建波表以精确控制相位，但发现它**依赖 `abs-env` 压制 `*warp*`** 才能定长建表，
这一层有不确定性。

最终改用 Audacity 自带的 `*sine-table*`，并让**左右包络互为镜像**（`panL + panR = 1`），
再由 `cos²=panL`、`sin²=panR` 取正根得到等功率增益。

这样做的收益是：**等功率关系不再依赖 LFO 的具体波形** —— 即使 LFO 不是标准正弦也成立。
（因为旋转是平移不变的，相位只决定"从哪里开始转"，不影响旋转本身是否正确。）

## 安装

1. 把 `plugins/` 里的 `.ny` 文件复制到 Audacity 的插件目录：
   - **Windows**：`C:\Program Files\Audacity\Plug-Ins\`（或便携版的 `Plug-Ins\`）
   - **macOS**：`/Applications/Audacity.app/Contents/PlugIns/`
   - **Linux**：`/usr/share/audacity/plug-ins/` 或 `~/.audacity-files/plug-ins/`
2. 重启 Audacity（或 `效果 → 插件管理器 → Rescan`）
3. **在插件管理器里勾选启用**：
   `效果` → `插件管理器` → 左上角 **`显示` 改成 `全部`** → 搜索 `8D` → 逐个勾选 → 确定

> ⚠️ **两个容易踩的坑**
> - `Rescan` **只负责登记，不会自动启用**新插件
> - 如果 `显示` 过滤器停在"已启用"，那些**未启用**的新插件根本不显示 —— 你会以为没扫描到

**子菜单分组**：6 个文件的 `$author` 都是 `8D环绕穿梭`。在
`编辑 → 偏好设置 → 效果 → 分组方式 → 按发布者分组` 下，它们会收进同名子菜单。

## 使用

### ⚠️ 只支持立体声输入

插件只处理 **2 声道**音频。这是最重要的一条：

> 如果素材是 **5.1 / 六声道**（比如从视频提取的音轨），插件**能跑完、不报错、但完全听不出变化**。

这不是 bug，是 Audacity 的 Nyquist 效果在多声道轨上的行为限制。**这个"静默失效"曾让我排查了很久**
（详见[复盘报告](docs/8D环绕插件-项目复盘报告.md)）。

**转换方法**：点音轨左侧控制面板 → `轨道` → `混音` → **`混音并渲染`**

### 操作步骤

1. 点音轨左侧灰色控制面板，让音轨选中
2. `Ctrl + A` 全选，确认底部右框显示**完整时长**（不是 `0.000 秒`）
3. `效果` → `8D环绕穿梭` → 选档位
4. 参数面板里点 `应用`

**验证是否生效**：看波形，应**上下两条交替变粗变细**。不要靠耳朵判断 —— 响度变化会骗过耳朵。

### 六个档位

| 档位 | 周期 | Haas | 保留原声 | 适用 |
|---|---|---|---|---|
| **初始 8D环绕** | 6.0 s | 18 ms | 25% | 第一次用，通用 |
| **爆款 TikTok 风** | 5.0 s | 22 ms | 20% | 短视频，出脑感更强 |
| **定番 10 秒** | 10.0 s | 18 ms | 25% | 整首歌，最耐听 |
| **舒缓睡眠** | 16.0 s | 15 ms | 40% | 长时间听，不晕 |
| **现场演出** | 4.0 s | 25 ms | 15% | 效果拉满 |
| **自定义** | 全可调 | 全可调 | 全可调 | 精调 / 存预设 |

### 周期取值依据

第三方 8D 工具的官方目安：旋转一周 **2–30 秒**可调，**8–12 秒为定番**，**2–4 秒过快会晕、不耐听**。

## 参数表（自定义档）

| 参数 | 默认 | 范围 | 说明 |
|---|---|---|---|
| 旋转周期 (秒) | 6.0 | 1–60 | 转一圈几秒，**最影响听感** |
| 用 BPM 卡点自动算周期 | 关 | 关/开 | 开 = 周期由 BPM 和拍数自动算 |
| BPM | 120 | 40–260 | 卡点用 |
| 每圈拍数 | 8 | 1–64 | 8 = 两小节一转 |
| 起始相位 (度) | 0 | -360~360 | 把转向点挪到重音上，**最直接的卡点手段** |
| 横扫深度 (%) | 100 | 0–100 | 100 = 完全左右 |
| 原声立体声宽度 (%) | 100 | 0–200 | 保留那部分原声的宽度 |
| Haas 延迟 (毫秒) | 18 | 0–40 | **出脑感关键**，0 = 关闭 |
| 低频保护 (Hz) | 200 | 0–1000 | 该值以下留中央 |
| 保留原声 (%) | 25 | 0–100 | 0 = 全湿（不推荐） |
| 输出归一化防削波 | 关 | 关/开 | 长音频会明显变慢 |

**卡点公式**：`周期 = 每圈拍数 × 60 ÷ BPM`
（例：BPM 120、8 拍一圈 → 4 秒）

> 说明：Audacity 的 Nyquist 效果拿不到节拍轨信息，所以**卡点无法做到全自动**，BPM 需手动填。

## 保存你的参数

调好一套参数后不用每次重调：
参数面板左上角 **`预设与设置`** → **`保存预设`** → 命名。
之后在任何预设的对话框里都能选它，也能导出成文本文件备份。

> Audacity 没有给 Nyquist 插件提供"读取已保存用户预设"的接口，
> 所以**自定义预设无法做成独立菜单项**，只能用原生预设系统。

### 测试音生成器

`8D测试音生成器.ny` 是 `$type generate`，在 `生成` 菜单里一键产出 16 秒立体声测试信号：
前 4 秒左右交替开关注（波形上两条明显交叉），后 12 秒 6 秒周期的强弱交替。
用来验证插件是否生效，不需要选区、不需要对话框选项。

## 开发记录：几个值得一说的坑

### 1. Nyquist 符号不能以数字开头

我最初把辅助函数命名为 `8d-mono`、`8d-tbl`。

XLISP 的读取器会把**以数字开头的 token 当成数字解析**（`8d` → `8`），
导致符号无法定义、**插件完全无法加载**。而且这是**读取阶段**的错误 —— 代码还没执行就失败了。

修复：全部改为 `s8d-` 前缀。

### 2. 逐行手写超越了自己核对能力的复杂度

测试音生成器**连崩三版**，分别有"左右声道混了同一路单声道""`pwlv` 拐点在同一时刻有两个取值"等问题。

教训：**在没有运行验证条件时，代码复杂度必须主动压到能逐行人工核实的程度**，
并优先使用已验证可用的原语。

### 3. `$name` 是插件身份，改名会破坏注册

为了让子菜单显示"自定义"，我把 `$name` 从 `"8D环绕穿梭"` 改成 `"自定义"`。

Audacity 用 `$name` 作为**插件身份**登记。改名后旧条目指向的文件对不上，
用户端报 **"该插件可能被删除"**。改回原值才恢复。

**这是一类通用问题**：很多系统用"名字"而非"路径"作为实体身份（Git 分支、数据库主键、K8s 资源同理）。
**看到"名称"字段，先问一句"它是标识还是标签"。**

### 4. 归一化写法会吃掉 400 MB 内存

最初用 `(mult 1.0 out)` 在不需要归一化时"原样返回"。但 `out` 是惰性求值的声音对象，
这个"原样返回"会触发它**被完整计算并缓存进内存**。

3 分钟立体声 @44.1 kHz ≈ 1600 万采样，约 **400 MB** 量级，可能拖死 Audacity。

修复：只在峰值真正超阈值时才求值，归一化默认关闭，并在标签上标注"长音频会慢"。

### 5. 最难的一个：多声道素材导致的静默失效

**现象**：插件完全不改变音频，也**没有任何报错**。

**真正的根因**：用户那条音轨是 **5.1 六声道**，而 Audacity 的 Nyquist 效果在多声道轨上
"能跑完、不报错、但结果看不出变化"。

**我走的最大弯路**：报错信息是"Nyquist 返回了过多的音频声道"。我一开始以为
"轨道是 2 声道"，于是**在错误的前提上做了四五轮诊断，全部白费**。

重新读这句话才反应过来：**"过多"是相对于轨道声道数而言的**。
返回 6 声道报错、返回 2 声道**也**报错 —— 唯一的解释是轨道声道数更多，也就是 6。

最终解法：`轨道 → 混音 → 混音并渲染` 折叠成 2 声道 →
**问题立刻消失，效果正常**。

> **这个案例的教训**：
> - **静默失效同时打破两个调试前提**（没有报错、输出看起来合法），必须主动构造客观证据
> - 读懂报错的确切含义，而不是把它当成模糊的"出错了"
> - **先隔离变量**：在干净的最小样本上复现，别在复杂真实素材上反复试
> - **连续几轮没有新信息就换方向** —— 那本身就是"你在错误前提上工作"的信号

## 已知限制

1. **只支持立体声输入** —— 多声道素材需先"混音并渲染"，且失败时**不报错**
2. **卡点不是全自动** —— Nyquist 效果拿不到节拍轨信息，BPM 需手动填
3. **不能做成独立的预设菜单项** —— 只能用 Audacity 原生预设系统
4. **`8D测试音生成器.ny` 未经充分验证** —— 它是在无法运行代码的条件下手写核对的
